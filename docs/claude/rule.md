# Rules

No project-specific conventions yet. The global rules in `~/.claude/rule.md` apply. Add Rust and frontend naming/style conventions here once the stack is chosen.

## UI conventions

- Design direction: **Modern** (contemporary desktop look in the spirit of Finder, Linear and Raycast): soft cool-grey surfaces, hairline borders, gentle shadows, rounded corners, one indigo accent, crisp stroke icons, short restrained transitions. File rows stay dense (22px), never cards.
- All colors, type sizes, spacing, radius and motion live as CSS custom properties in `src/tokens.css`; `src/styles.css` uses only `var(--...)`, no raw hex. Add or change a value in the tokens file first.
- Theme follows `prefers-color-scheme` (light and dark defined in `tokens.css`); there is no toggle.
- Icons are inline SVG components in `src/icons.tsx` (stroke, `currentColor`, tinted by token). No icon font, no image CDN.
- Offline rule: the desktop app makes no runtime network request for UI assets. System font stack (`system-ui`, `ui-monospace` for lists) only; if a font is ever wanted, bundle the file under `src/` and reference it locally, never Google Fonts or a CDN.
- WebKit (macOS and Linux webviews) is the target: avoid CSS that WebKit lacks; progressive features only (e.g. `::-webkit-scrollbar` is used for a fixed-width list scrollbar so the column header stays aligned).
- Modal dialogs (file operations): one open at a time (`ops_store`), a scrim (`--scrim`) and a card with `--shadow-modal`, role="dialog", focus moves into the dialog and back to the active panel on close, Tab stays inside. Esc cancels, Enter confirms (a focused button keeps its own Enter), the primary action is the `data-autofocus` element. A destructive permanent action is labelled as such ("Delete permanently") and the dialog says what happens (Trash for local, permanent on the server). Delete, New folder and Rename show a busy dialog without Cancel while they run; a copy, move or drop never does: it becomes a job in the transfer queue (below).
- Collapsible form section (`.section-toggle`, `aria-expanded` / `aria-controls`): collapsed by default unless a value is set or a server error belongs to it; optional fields show their defaults as placeholders and a visible label; an imported value is filled as an editable preview and marked touched so its error shows at once.
- Function keys act only when no dialog is open.
- Visual changes must not touch store logic, commands or keyboard handling.
- Sorting (`src/browse/sort.ts`, state in each panel slice as `sort`): one pure comparator, the store keeps `entries` sorted with it (after every listing, page load and sort change) and `buildRows` only prepends `..`. Header click and the context menu both call the store actions `sortBy` / `reverseSort`; never re-implement the order elsewhere. Folders stay above files and sort by name only (direction applies to them for Name only); Name and Ext use a natural, case-insensitive collator; ties fall back to Name ascending. The cursor follows its item by name when the order changes. Sort is per panel, survives `setSource`, and is not persisted. A server panel with `nextToken` shows the "sorted over loaded items" hint and a "Load all" action (`loadAll`, cap 20,000 items). Folders show `<DIR>` in the Ext column, their Size cell is empty.
- Context menu (`src/browse/context_menu.ts`): the items are a data list (`id`, `label`, `shortcut`, `enabled`, `run`) built by `buildMenuItems`; to add an action append one entry. `run` must call the same flow function the F-key calls, never duplicate operation logic. Right-click on an unmarked row selects only it; on a marked row it acts on all marks; empty space offers New folder only. Ignored while a dialog is open. role=menu / menuitem, ArrowUp/Down, Enter, Esc (focus back to the panel), Tab closes; closes on outside mousedown, blur, scroll, resize. The native webview menu is suppressed on panels only.
- Drag and drop (`src/browse/drag_drop*.ts`): pointer events only, never the HTML5 `draggable` API. Row elements need `data-row-name` (and `data-row-dir` / `data-row-up`), the panel root `data-panel`; identify rows by name, not index. Cues are token classes (`drop-copy`, `drop-move`, `drop-refused`) on the panel or row; a new drop target must go through `resolveDrop` and the `startTransferOf` flow, never start an operation itself. Esc cancels, refusals show a toast, nothing runs on a refused drop.
- Presign dialogs (`src/ops/presign_*.ts(x)`): same modal rules as above (shared shell `modal.tsx`). Expiry is a radiogroup of preset buttons (`role=radio`, `aria-checked`) plus Custom with a value and unit; the default is 1 hour. A warning about who can read a URL uses the `.caution` class (warn tokens), not `.notice` (green). Status messages after Copy or Save use `toast.tsx` (`.toast`, `.toast.failed`), never a dialog. Anything holding a URL stays in the dialog state only; do not copy URLs into other stores.
- Panel split (`src/browse/panel_split.ts`, `panel_splitter.tsx`, `splitRatio` in `browse_store`): the layout slice holds the left panel's share of the free width (container minus the 8 px splitter), range 0.2..0.8, default 0.5; always set it through `setSplitRatio` (clamps and persists to localStorage key `s3c.panel-split.v1`; every storage access is try/catch, stored garbage falls back to 0.5). `.panels` is a 3-column grid driven by `--col-left` / `--col-right` (`NNNfr`) with `minmax(240px, ...)` so the minimum width holds on window resize; JS clamps with the live container width during drag and keyboard. The splitter is a direct child of `.panels`, outside both `[data-panel]` roots, which is why `hitTest` never returns it; keep it outside. The narrow media query resets the columns to one and hides the splitter. Panel content that needs fewer columns when narrow uses `@container` on `.panel`, not a viewport query.
- Column widths (`src/browse/panel_columns.ts`, `column_resizer.tsx`, `columnWidths` in `browse_store`): the layout slice holds Ext, Size and Date widths per side (the user's values; Name is the flexible column). Always set them through `setColumnWidth` / `resetColumnWidth` (clamps to `COLUMN_LIMITS` and persists all sides to localStorage key `s3c.panel-columns.v1`; every storage access is try/catch, garbage falls back per field). `FilePanel` fits the stored widths to its measured width with `fitWidths` (Date, then Size, then Ext shrink; Name keeps `NAME_MIN_PX`; the stored values are never rewritten) and publishes the result as `--w-ext`, `--w-size`, `--w-date` on the panel root; the single `.row` template in `styles.css` reads them for the header and every row, so never put a fixed column width anywhere else. `HIDE_DATE_PX` (420) mirrors the `@container (max-width: 420px)` rule that hides Date: keep the two in sync. The border is a `role="separator"` in the header cell beside the sort button (never inside it) and stops key propagation so the panel keys (Tab, Home) do not also run.
- Transfer queue (`src/queue/`): a docked section above the F-key bar, never a modal. Collapsed it is one line (heading, `role=status` text from `statusText`: "Idle" or "2 running, 1 queued, 40%"); the header is a real button with `aria-expanded` / `aria-controls`, and Esc inside the panel collapses it and puts the focus back on the header. Rows are `role=listitem` with `data-state`, a `role=progressbar` (`aria-valuenow` = job percent), the current item, bytes done/total, speed, ETA and item counts, and the buttons that `buttonsFor(state)` allows (Cancel for queued or running, Retry for failed or cancelled, Dismiss for finished; none while cancelling): to change which state offers what, edit that table, not the component. Failures sit behind an "N failed" expander (`aria-expanded`), capped by the backend with "and N more". Speed and ETA are pure functions of the samples (`speedOf`, `etaSeconds`); the reducer is the only code that writes job state and is fed by the backend events only; a late progress event never revives a finished row. Styles use tokens only (`.queue-*` in `styles.css`, state colors from `--accent`, `--ok`, `--danger`, `--warn`, `--muted`), no raw hex. A flow that starts a transfer must go through `transferStart` + `registerJob` (as `startJob` in `ops_flow.ts` does), never call the engine itself. Failures of Cancel, Retry and Dismiss are shown as a toast.
- Viewer and editor (`src/viewer/`): the large in-window modal (`.viewer` inside `.scrim`, `role="dialog"`, `aria-modal`, Tab trapped, focus goes to the editor and back to the source panel on close). Keys: Esc closes (asks first when dirty; ignored when CodeMirror or a table cell already handled it, check `defaultPrevented`), Cmd/Ctrl+S saves. Questions over the viewer (unsaved changes, changed on disk or on the server, invalid JSON, save-as-copy name) are nested `Modal`s from `ops/modal.tsx`; a destructive choice is never the focused button (Cancel is). Colors only through tokens (the CodeMirror theme uses `var(--...)`, so light and dark need no second theme). Everything that imports CodeMirror or the grid must be reached only through `viewer_host.tsx` (lazy), so the main bundle does not grow. Never read the editor text with `doc.toString()`; use `state.sliceDoc()` so CRLF survives. New file kinds: extend `fileKind` in `text_kind.ts`. The table grid renders every column of the visible rows (rows are windowed).
- Settings popover and unlock wait (`src/security/`, `master_key_screen.tsx`): the popover is a `.popover-wrap` (relative) holding a button with `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` and a `role="dialog"` `.popover` that opens under it, right-aligned; choices are the shared `.segmented` radiogroup (`role=radio`, `aria-checked`), so a new setting reuses it; Esc closes it and focuses the button, an outside mousedown closes it, the checked choice takes focus on open. Settings go through `settings_store` (Rust validates and owns the file; a failed save keeps the old value and shows `role=alert` text). The unlock wait is a `.caution` with `role="status"`, never `.alert`, and the Unlock button is disabled while it runs; the countdown is computed from a wall-clock end, not by decrementing. The idle timer stays pure (`idle_timer.ts`); the lock itself always goes through `App.lock`.
- Selection (`src/browse/selection.ts`, store actions in `browse_store`): the marked set is the only selection; never add a second one. Change marks only through the store actions (`selectOnly`, `toggleAt`, `extendSelection`, `markAll`, `invertSelection`, `setMarks`, `applyPattern`), never write `marked` elsewhere; ".." is never marked. Marked rows use the `--mark` token (`aria-selected` rows and the `.band` rectangle), no second color. Escape clears marks only when no dialog, context menu or viewer is open. A new bulk action must set `selectionNote` through `withMarks` so it is announced.
- Panel reload (`src/browse/panel_loader.ts` `reloadPanel`, `reload_state.ts`, `reload_triggers.ts`): a reload goes through `reloadPanel`, never a second loader; it keeps rows while loading and keeps cursor, marks and anchor by name (see architect.md "Panel reload"). Header button `.reload-btn` (`aria-label="Reload"`, spins with `.spinning`), menu item id `refresh`, Cmd/Ctrl+R handled in `reload_triggers.ts` (F5 stays Copy). New code that must refresh a panel after changing files calls `reloadPanel` or `refreshPanel`.
