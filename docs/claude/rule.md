# Rules

No project-specific conventions yet. The global rules in `~/.claude/rule.md` apply. Add Rust and frontend naming/style conventions here once the stack is chosen.

## UI conventions

- Design direction: **Modern** (contemporary desktop look in the spirit of Finder, Linear and Raycast): soft cool-grey surfaces, hairline borders, gentle shadows, rounded corners, one indigo accent, crisp stroke icons, short restrained transitions. File rows stay dense (22px), never cards.
- All colors, type sizes, spacing, radius and motion live as CSS custom properties in `src/tokens.css`; `src/styles.css` uses only `var(--...)`, no raw hex. Add or change a value in the tokens file first.
- Theme follows `prefers-color-scheme` (light and dark defined in `tokens.css`); there is no toggle.
- Icons are inline SVG components in `src/icons.tsx` (stroke, `currentColor`, tinted by token). No icon font, no image CDN.
- Offline rule: the desktop app makes no runtime network request for UI assets. System font stack (`system-ui`, `ui-monospace` for lists) only; if a font is ever wanted, bundle the file under `src/` and reference it locally, never Google Fonts or a CDN.
- WebKit (macOS and Linux webviews) is the target: avoid CSS that WebKit lacks; progressive features only (e.g. `::-webkit-scrollbar` is used for a fixed-width list scrollbar so the column header stays aligned).
- Modal dialogs (file operations): one open at a time (`ops_store`), a scrim (`--scrim`) and a card with `--shadow-modal`, role="dialog", focus moves into the dialog and back to the active panel on close, Tab stays inside. Esc cancels, Enter confirms (a focused button keeps its own Enter), the primary action is the `data-autofocus` element. A destructive permanent action is labelled as such ("Delete permanently") and the dialog says what happens (Trash for local, permanent on the server). A running operation shows a busy dialog without Cancel (cancel arrives with step 4).
- Collapsible form section (`.section-toggle`, `aria-expanded` / `aria-controls`): collapsed by default unless a value is set or a server error belongs to it; optional fields show their defaults as placeholders and a visible label; an imported value is filled as an editable preview and marked touched so its error shows at once.
- Function keys act only when no dialog is open.
- Visual changes must not touch store logic, commands or keyboard handling.
- Sorting (`src/browse/sort.ts`, state in each panel slice as `sort`): one pure comparator, the store keeps `entries` sorted with it (after every listing, page load and sort change) and `buildRows` only prepends `..`. Header click and the context menu both call the store actions `sortBy` / `reverseSort`; never re-implement the order elsewhere. Folders stay above files and sort by name only (direction applies to them for Name only); Name and Ext use a natural, case-insensitive collator; ties fall back to Name ascending. The cursor follows its item by name when the order changes. Sort is per panel, survives `setSource`, and is not persisted. A server panel with `nextToken` shows the "sorted over loaded items" hint and a "Load all" action (`loadAll`, cap 20,000 items). Folders show `<DIR>` in the Ext column, their Size cell is empty.
- Context menu (`src/browse/context_menu.ts`): the items are a data list (`id`, `label`, `shortcut`, `enabled`, `run`) built by `buildMenuItems`; to add an action append one entry. `run` must call the same flow function the F-key calls, never duplicate operation logic. Right-click on an unmarked row selects only it; on a marked row it acts on all marks; empty space offers New folder only. Ignored while a dialog is open. role=menu / menuitem, ArrowUp/Down, Enter, Esc (focus back to the panel), Tab closes; closes on outside mousedown, blur, scroll, resize. The native webview menu is suppressed on panels only.
- Drag and drop (`src/browse/drag_drop*.ts`): pointer events only, never the HTML5 `draggable` API. Row elements need `data-row-name` (and `data-row-dir` / `data-row-up`), the panel root `data-panel`; identify rows by name, not index. Cues are token classes (`drop-copy`, `drop-move`, `drop-refused`) on the panel or row; a new drop target must go through `resolveDrop` and the `startTransferOf` flow, never start an operation itself. Esc cancels, refusals show a toast, nothing runs on a refused drop.
- Presign dialogs (`src/ops/presign_*.ts(x)`): same modal rules as above (shared shell `modal.tsx`). Expiry is a radiogroup of preset buttons (`role=radio`, `aria-checked`) plus Custom with a value and unit; the default is 1 hour. A warning about who can read a URL uses the `.caution` class (warn tokens), not `.notice` (green). Status messages after Copy or Save use `toast.tsx` (`.toast`, `.toast.failed`), never a dialog. Anything holding a URL stays in the dialog state only; do not copy URLs into other stores.
- Panel split (`src/browse/panel_split.ts`, `panel_splitter.tsx`, `splitRatio` in `browse_store`): the layout slice holds the left panel's share of the free width (container minus the 8 px splitter), range 0.2..0.8, default 0.5; always set it through `setSplitRatio` (clamps and persists to localStorage key `s3c.panel-split.v1`; every storage access is try/catch, stored garbage falls back to 0.5). `.panels` is a 3-column grid driven by `--col-left` / `--col-right` (`NNNfr`) with `minmax(240px, ...)` so the minimum width holds on window resize; JS clamps with the live container width during drag and keyboard. The splitter is a direct child of `.panels`, outside both `[data-panel]` roots, which is why `hitTest` never returns it; keep it outside. The narrow media query resets the columns to one and hides the splitter. Panel content that needs fewer columns when narrow uses `@container` on `.panel`, not a viewport query.
