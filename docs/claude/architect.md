# Architecture

Design from the project owner; the vault, browsing (step 2) and its dual-pane UI are implemented; transfers and edit are not yet.

- **Shell**: Tauri desktop app (Rust backend + web frontend).
- **UI**: Total Commander-style dual pane. Two independent panels, each listing a directory/prefix with columns Name, Ext, Size, Date; a function-key bar at the bottom (F3 View, F4 Edit, F5 Copy, F6 Move, F7 New Folder, F8 Delete, Alt+F4 Exit); keyboard-driven navigation. Copy/Move between the two panels is the core workflow.
- **Scope**: manage directories (S3 prefixes) and files (objects) on a MinIO server (S3-compatible API, not AWS S3 itself). MinIO usually needs path-style addressing; for local testing, run a MinIO container from the shared `lab-infra` stack if it has one, otherwise ask before adding one.
- **Profiles**: multiple profiles, each holding a custom endpoint URL (no AWS-only assumptions: no fixed region/endpoint resolution, path-style addressing may be needed) and its secrets.
- **Security**: profile secrets live in the app's own encrypted vault (see Vault below), not the OS keychain; a master key is required to log in (unlock) the app. An optional OS-keychain "remember on this device" is planned with a silent fallback to the master-key prompt (see `docs/implement/s3-commander-roadmap.md`).
- **S3 client**: `aws-sdk-s3`, one client per unlocked profile (endpoint URL, path-style, static credentials, checksums only when required); the bucket is passed per request, so one client serves every bucket.
- **Platforms**: macOS and Linux. The vault is plain files, so it behaves the same on both; do not make the OS keychain a hard dependency (minimal Linux setups have no Secret Service).

## Vault (implemented)

- `src-tauri/src/vault.rs` is plain Rust (no Tauri dependency, unit-tested). `lib.rs` holds a `Mutex<Vault>` in Tauri managed state and exposes thin commands: `vault_status`, `vault_create`, `vault_unlock`, `vault_lock`, `profile_list`, `profile_save`, `profile_delete`.
- File `vault.json` in the Tauri app data dir: JSON `{version, salt, nonce, ciphertext}` (base64). Master key -> Argon2id (random 16-byte salt) -> 32-byte key -> XChaCha20-Poly1305 over the whole profile list; fresh random 24-byte nonce on every save, file replaced atomically (tmp + rename).
- No stored master-key hash: a wrong key fails on the AEAD auth tag, as does a tampered file. Vault states: no file = create, file = unlock.
- The derived key lives only in the managed state (zeroized on lock/drop) and is never sent to the frontend. `profile_list` returns profiles without `secret_key`; `profile_save` with an empty secret on an existing profile keeps the stored secret. `Vault::get_profile` (with secret) is internal, for the later S3 step.
- Profile = id, name, endpoint URL, access key, secret key, region (default `us-east-1`).
- **Profile validation**: `src-tauri/src/profile_rules.rs::validate_profile_input` is the one authoritative place (no Tauri dependency); `Vault::save_profile` calls it and fails with `VaultError::Validation(Vec<FieldError>)`, at most one `{field, message}` per field (`name`, `endpoint`, `access_key`, `secret_key`, `region`). `profile_save` returns `ProfileSaveError {message, fields}`; other commands are unchanged. Messages never contain the checked values. The frontend mirror is `src/profile/validate_profile.ts`; both are tested against `src/profile/validation_cases.json`. Rules: name trimmed, required, max 64, unique case-insensitively among the other profiles; endpoint trimmed, `http`/`https` only, host required, no whitespace, user info, query, fragment or path, port 1..65535, normalized to `scheme://host[:port]` (lowercase host, no trailing slash); access key trimmed, required, no whitespace or control characters; secret required on create, blank on edit keeps the stored one, never trimmed, no control characters; region trimmed, default `us-east-1`, `[a-z0-9-]` up to 32. `http://` is allowed with a non-blocking warning. Save never tests connectivity (the Test button does).

## Browse (implemented, roadmap step 2)

- `src-tauri/src/s3.rs` (no Tauri dependency): `client_config_builder(profile)` sets endpoint URL, `force_path_style(true)`, region, static credentials and `WhenRequired` request/response checksums (no `aws-config`). `list_buckets`, `list_dir(bucket, prefix, token)` return one page (delimiter `/`, prefixes become dirs, keys files, the key equal to the prefix is skipped, `next_token` for the next page), `check_connection` backs `profile_test`. SDK errors map to `AppError::S3` with a readable message.
- `src-tauri/src/local.rs`: `list_dir(path)` over `std::fs`, dirs first, hidden files included, IO errors returned as readable `AppError::Local`. An empty path means the home directory; the frontend never touches the file system.
- `src-tauri/src/app_error.rs`: `AppError` serializes to its message string. New commands return it; the older vault commands still return `String`.
- `lib.rs`: `ClientCache` (managed state) holds the client of the one active profile; it is cleared on `vault_lock`, `profile_save`, `profile_delete` and replaced when another profile is used. `profile_test` always builds a fresh client. Commands: `s3_list_buckets`, `s3_list_dir`, `local_list_dir`, `profile_test`, `profile_duplicate` (copies the secret inside the vault, returns a summary only).
- Frontend state: `src/browse/browse_store.ts` (Zustand) holds `left`/`right` panel slices (source, path, entries, nextToken, cursor, marked, scrollTop), `active`, `profileId`, `buckets`. `setProfile` (on change) and `lock` reset only bucket panels; Local keeps its state. No secrets in the store. `panel_loader.ts` loads listings and drops responses that arrive after the panel moved on.
- Not built yet: function keys, context menu, transfers (steps 3 and later). The S3 pagination loads the next page when the cursor nears the end of the loaded rows.
