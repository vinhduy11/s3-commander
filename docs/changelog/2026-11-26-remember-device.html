Remember on this device (step 6b)

Specs

  • Opt-in option (default off) in the Settings popover that keeps the vault's 32-byte derived key (never the master key text) in the OS keychain, service dev.local.s3commander, fixed account, base64.
  • Used only at app launch (vault_unlock_remembered); Lock and idle auto-lock need the master key again; remembered unlocks do not count in the unlock throttle.
  • Stale or failing key: deleted silently, master-key screen shown. Off, Forget, failed decrypt delete the entry; refresh after the Argon2 upgrade changed the key.
  • Keychain behind a KeyStore trait with SystemKeyStore (keyring crate) and an in-memory fake; unavailable keychain: option disabled, "Not available on this system", no error. Documentation: safety, architect, new deployment.md, commands, README, CHANGELOG.

Actions

  • Rust: key_store.rs (trait, SystemKeyStore, test-only MemoryKeyStore, one #[ignore] real-keychain test), remember.rs (enable, forget, status, unlock_remembered with LaunchGate, unlock_with_master with refresh), settings.rs flag remember_on_device and save_from_ui, vault.rs derived_key / unlock_with_key (decrypt path shared via open_file_with), lib.rs commands and managed state; dependency keyring 4.2 (default features).
  • Frontend: security/launch_unlock.ts, settings store and popover (off / on with Forget / not available), "Unlocking..." state in MasterKeyScreen, App tries the remembered key once at mount, CSS.
  • Tests written first (red saved: compile errors for Rust, 9 failed tests plus a missing module for Vitest), then green: Rust 304 passed, 2 ignored; Vitest 541 passed; cargo check and npm run build clean, zero warnings.

Tradeoffs

  • Derived key instead of a data-key redesign: no format change, but the stored key is equivalent to the master key for that vault file and changes when the salt changes (handled by the refresh).
  • One-shot LaunchGate in Rust rather than a frontend rule, so a compromised or buggy UI cannot re-unlock after a lock.
  • A remembered launch cannot run the Argon2 upgrade (no master key); it happens at the next master-key unlock.
  • Forget and the unticked box are the same action (delete entry, flag off); the Forget button is a visible shortcut.
  • keyring v4 default features chosen: zbus Secret Service avoids system libdbus; it also compiles the Windows store, unused.
  • An unreadable value in the keychain is treated as absent instead of an error.

Measured vs inferred

Measured: the test, check and build results above on this Mac; popover screenshots (Chromium with a mocked __TAURI_INTERNALS__, three states, light and dark).

Not exercised / inferred: the real macOS Keychain (prompts, access rules), the Linux Secret Service and the Linux build, the Tauri window, an Argon2 vault upgrade with a stored key against the real keychain (the fake store covers the logic), signing and DMG build (documented, unverified).
