In-app update check and GitHub Actions workflows

Specs

  • Tauri updater plugin (desktop) and process plugin (relaunch) with minimal capabilities; signed updater artifacts; endpoint on GitHub Releases latest.json; public key in tauri.conf.json; identifier, product name and version unchanged.
  • Update UX: quiet check once per launch after unlock (not in dev, silent on errors), "Check for updates" button with visible results, update dialog (versions, notes, progress, Restart now or Later), persisted setting "Check for updates at launch" (default on), warning before installing during a transfer, only the endpoint URL is contacted.
  • ci.yml (push to main, pull requests, macOS and Linux, version-match check) and release.yml (tag v* or manual, tag equals config version, macOS arm64 and Intel, Linux deb and AppImage, draft release with updater files).
  • Docs: deployment, safety, architect, rule, README, CHANGELOG.

Actions

  • Rust: plugins registered in lib.rs; settings.rs gets check_updates_at_launch (serde default true), the settings save preserves remember_on_device.
  • Frontend: src/update/ (logic, api, store, dialog, launch hook), Settings popover (toggle, button, status line, data note), top-bar "Update X" button, dialog rendered in App.tsx.
  • Workflows reviewed: runner names (macos-latest, macos-15-intel, ubuntu-22.04), Rust target for the Intel build, rust-cache workspace, tag/version comparison, least-privilege permissions (contents: write only on the release job).
  • The branch was merged with main (no textual conflicts); 308 Rust and 695 frontend tests pass after the merge; cargo check has no warnings; npm run build passes.

Tradeoffs

  • Draft release: a human publishes it, so a bad build never reaches latest.json by itself; costs one manual click.
  • No download cancel (the plugin has none); the dialog says so. Install during a transfer asks (wait, install anyway, cancel).
  • Launch check silent on failure so a missing network never nags; a manual check shows the error.
  • Builds are unsigned for Apple (updater signature only); Apple signing is left as commented variables.
  • Updater key has no password to keep the secret setup to one value; custody is documented.

Measured vs inferred

  • Measured: Rust and vitest suites, cargo check, frontend build, YAML parse of both workflows, the version check script run locally, Chromium mock screenshots of the UI.
  • Inferred (only verifiable on GitHub or on a real build): that the workflows run, that macos-15-intel and the Linux packages work, that tauri-action@v0 publishes latest.json with the expected shape, that a real signed update downloads and installs, the Linux build, the Tauri window behavior.
