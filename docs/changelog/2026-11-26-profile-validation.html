Profile validation (add and edit)

Specs

Owner requirement: when adding a profile there must be validation. Rust is authoritative and returns per-field errors; the form mirrors the rules for instant inline feedback. Rules: name required, trimmed, max 64, unique case-insensitively (a profile may keep its own name); endpoint is an http or https URL with a host, no user info, query, fragment or path, port 1..65535, normalized (trimmed, no trailing slash); http:// allowed with a non-blocking warning; access key required without whitespace or control characters; secret key required on create, blank on edit keeps the stored one, never trimmed, no control characters; region optional (default us-east-1), [a-z0-9-] up to 32. Connectivity is not checked by Save; the secret never appears in an error.

Actions

  • New src-tauri/src/profile_rules.rs: validate_profile_input (the one rule set) and FieldError. Uses the url crate (already in the lock file) so parsing matches the browser's URL.
  • vault.rs: save_profile calls it; VaultError::Validation replaces the old required-field check.
  • app_error.rs and lib.rs: ProfileSaveError {message, fields} is the error of profile_save only.
  • Frontend: src/profile/validate_profile.ts, new src/screens/profile_form.tsx (inline errors after a field is touched, Save disabled while invalid, http warning, server errors per field), profiles_screen.tsx (saved notice with a Test connection button), --warn tokens and field styles.
  • Tests (written first, red then green): 39 Rust tests including a shared table of 54 cases (src/profile/validation_cases.json) read by both Rust and vitest; vault tests for uniqueness, self-edit, secret on create and edit, normalization and no secret in errors; 89 vitest tests including form behavior.
  • Docs: README structure, CHANGELOG, docs/claude/architect.md.

Tradeoffs

  • Two implementations (Rust, TS) instead of one: needed for instant feedback; the shared case table keeps them aligned. The table checks fields and normalized values, not message text.
  • Access key and name are trimmed before validation (as before) so a pasted trailing newline is forgiven; whitespace inside the access key is rejected. The secret is never trimmed.
  • Endpoint is normalized by WHATWG parsing, so the host is lowercased and a default port (80, 443) is dropped.
  • profile_save alone gets the structured error; other commands keep string errors, so nothing else changes.
  • Errors show only for touched fields, so an empty new form is not red, but Save stays disabled.
  • Not covered: profile_duplicate still names the copy "<name> (copy)", which can repeat or exceed 64 characters; existing stored profiles are not re-validated until edited.
