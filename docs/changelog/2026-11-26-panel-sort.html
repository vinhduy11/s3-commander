Sorting in the panels (step 3e)

Specs

  • Click a column header (Name, Ext, Size, Date) to sort a panel, click again to reverse; arrow and aria-sort show the active column; headers are keyboard-focusable buttons.
  • Per-panel sort in the Zustand slice, default Name ascending, survives view and source switches, not persisted across restarts.
  • Rules: .. first; folders above files, sorted by name only; Name and Ext case-insensitive with natural numbers; ties by Name ascending; cursor follows its item by name.
  • Server listings are paginated: while pages remain, footer hint "sorted over loaded items" and a "Load all" action capped at 20,000 items. No Rust change.
  • Column fix: <DIR> moves to the Ext column; folder Size cell is empty.
  • Empty-area context menu gets Sort by Name / Ext / Size / Date and Reverse order, calling the same store actions.

Actions

  • New src/browse/sort.ts (comparator sortEntries, nextSort, types) with sort.test.ts.
  • browse_store.ts: sort in the panel slice, actions sortBy and reverseSort, setSource keeps the sort, setListing sorts with it, cursor follows by name after a re-sort and after an appended page. The old inline sort was removed.
  • panel_loader.ts: loadAll(side, cap = 20000) over loadMore; stops on error, no progress, or the cap (message through the panel error line).
  • file_panel.tsx and styles.css: header buttons inside columnheader cells, <DIR> in Ext, footer hint with a Load all button (server panels with a next token only).
  • context_menu.ts and context_menu_view.tsx: sort entries in the empty-area list (optional checked, rendered as menuitemradio); keyboard selectors accept menuitem*.
  • Tests: comparator, store (per panel, source switch, cursor), loadAll (all pages, cap, error), panel (header cycle, aria-sort, <DIR>, hint), context menu. Red run first, then green (170 tests); npm run build passes.
  • Visual check: Chromium mock screenshots (Vite on a spare port, in-page Tauri mock, fake names) in light and dark.

Tradeoffs

  • The store keeps entries sorted (sorted once per change) instead of sorting inside buildRows on every render: a 20,000-row panel re-renders on scroll and would re-sort each time. buildRows only prepends ...
  • Sort by Size, Date or natural Name on a server panel covers loaded pages only (S3 lists in key order); hence the hint and the capped Load all instead of server-side sorting.
  • The cap message reuses the panel error line rather than a new notice field: smaller change, but it shows in alert style and hides the hint until the next listing.
  • loadAll stops when a page adds no items, so an empty page that still has a token ends the loop; the user can press Load all again.
  • Intl.Collator (numeric, base sensitivity) instead of a hand-written natural compare; order of non-ASCII names follows the system locale.
