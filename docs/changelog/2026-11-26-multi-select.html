Multi-select in the file panels

Specs

  • Owner request (top priority): the app lacks multi select. The marked set stays THE selection consumed by F5, F6, F8, F9, drag, presign and the context menu.
  • Mouse: plain, Cmd/Ctrl and Shift click; anchor per panel. Keyboard: Shift+movement keys, Cmd/Ctrl+A, Esc, *, + and - (glob pattern modal with preview count). Rubber band from empty list space. Empty-area menu entries. Accessibility: listbox, aria-selected, polite announcement, footer "N selected, size".
  • Out of scope: what operations do with the selection, new operations, go-to-path, remember-last-folder, the updater.

Actions

  • New: selection.ts (pure rules), selection_flow.ts, rubber_band.ts, ops/pattern_dialog.tsx; two test files (selection.test.ts, multi_select_panel.test.tsx).
  • Changed: browse_store.ts (anchor, selectionNote, seven actions), file_panel.tsx (click variants, keys, aria, band, live region, footer), context_menu.ts (four entries), ops_store.ts / ops_dialogs.tsx (new dialog kind), styles.css (mark background, band, sr-only, menu separator), one existing context-menu test updated for the new first entries.
  • Docs: README structure, CHANGELOG, architect (selection model and shortcut table), rule.

Tradeoffs

  • Selection logic lives in the click handler, not pointer-down: the drag module already swallows the click after a real drag, so a pointer-down on a marked row keeps the drag set and only a click without drag clears the marks. No change to the drag module.
  • Cmd/Ctrl+click after a plain click turns the plain-clicked row into a real mark (otherwise the first row would silently drop out). Only when the cursor row is the anchor, so a fresh load does not mark the first row.
  • Pattern dialog is a new kind in the existing ops_store dialog union, so it inherits one-dialog-at-a-time, focus trap and the "function keys act only when no dialog is open" rule. "Select" adds to the marks, "Deselect" removes (Total Commander style).
  • Rubber band hit-testing is vertical only (rows span the full list width and the press is inside the list, so the horizontal test is always true). A click on empty space without drag clears the marks (Shift/Cmd/Ctrl keeps them).
  • The list became role="listbox" with option rows; the footer wording changed from "size in N marked" to "N selected, size".
  • On macOS, Ctrl+click is a right-click and opens the menu; Cmd+click is the Mac gesture, Ctrl+click works on Linux.

Measured

  • npm test: 40 files, 594 tests pass (red run first: 26 failures plus a file that could not import). npm run build ok.
  • Chromium mock screenshots (fake data, light and dark): Cmd-click set, Shift range, Shift+Arrow, Cmd/Ctrl+A, rubber band in progress, pattern modal with count, empty-area menu. Resulting marked sets were read back from the DOM and matched.
