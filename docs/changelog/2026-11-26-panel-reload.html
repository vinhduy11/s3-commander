Reload a panel's listing

Specs

  • Owner request: when a local or server folder changes there was no way to reload the panel.
  • Reload button in each panel header (spinning while loading, disabled without a source); Cmd/Ctrl+R for the active panel (F5 stays Copy); "Refresh" in the row and empty-space context menus.
  • Keep context: old rows stay while loading, cursor follows the entry name, marks and anchor kept for names that still exist, scroll, sort, column widths and splitter untouched. Server: first page again. Failure keeps rows and shows the error. A vanished Local folder falls back to the nearest parent with a footer notice. Empty server prefix is an empty listing.
  • Local panels reload silently when the window regains focus (debounce about 1 s; skipped for dialog, viewer, drag, rubber band, loading; never server panels). Always on.

Actions

  • New reload_state.ts (pure keepAfterReload) and reload_triggers.ts (installReloadKey, installFocusReload, reloadShortcut).
  • panel_loader.ts: openPath and new reloadPanel share one internal load (same request counter, stale drop and loading handling); parent fallback walks up with parentOf.
  • browse_store.ts: setListing option keep, notice field and setNotice. file_panel.tsx: header button and notice in the footer. context_menu.ts: Refresh item last in both menus. browser_screen.tsx: installs the two triggers. icons.tsx: RefreshIcon. styles.css: .reload-btn.
  • Tests first (17 failing, saved), then green: reload_state.test.ts, panel_reload.test.ts, reload_ui.test.tsx, reload_menu.test.ts, reload_keys.test.ts; two expectations in context_menu.test.ts extended with the new last item.
  • Docs: README structure, CHANGELOG, architect and rule notes.

Tradeoffs

  • Reused the existing loader with a reload flag instead of a second loader, so the race rules exist once. Cost: load has three small option branches.
  • Cmd/Ctrl+R always calls preventDefault, even while a dialog or input is active, so the webview can never reload and lose state; it just does nothing there.
  • Focus reload is silent (no loading flag, no error) so a background refresh never flashes the footer; a real failure shows only when the user reloads by hand. A rubber band is detected by its .band element because its state is local to its hook (no store was added).
  • Focus reload instead of a filesystem watcher: simplest, no new Rust dependency, but changes made while the window stays focused are not seen until a manual reload. A notify-based watcher is a possible follow-up.
  • The existing refreshPanel after operations still resets marks and scroll (unchanged, out of scope).

Measured

  • npm test: 45 files, 628 tests pass; npm run build ok.
  • Chromium mock screenshots (fake data, in-page Tauri mock) in light and dark: idle, spinning, content changed with cursor and marks kept, vanished folder notice, menu with Refresh. In the mock, Ctrl+R did not reload the page; the kept cursor and marks were read back from the DOM.

Inferred, not exercised

  • The real Tauri window and WebKit: window focus events when returning from Finder, Cmd+R inside the real webview (the Tauri/WebKit default reload shortcut), real filesystem changes, a real server, timing of a slow listing.
