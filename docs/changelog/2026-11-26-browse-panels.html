Browse panels (roadmap step 2)

Specs

  • Build an S3 client from a profile (custom endpoint, path style, region, static credentials, checksums only when required) and list buckets and prefixes with pagination.
  • Local listing through Rust; one app error type with readable messages; commands s3_list_buckets, s3_list_dir, local_list_dir, profile_test, profile_duplicate.
  • Dual-pane UI: Name/Ext/Size/Date, keyboard navigation, source selector per panel, virtualised list, profile switcher and Lock; function-key bar rendered disabled. Panel state in a Zustand store; S3 side resets on profile switch or lock, Local keeps state.
  • Out of scope: copy, move, delete, rename, upload, download, drag and drop, context menu.

Actions

  • Rust: app_error.rs, s3.rs, local.rs; Vault::duplicate_profile; ClientCache and the new commands in lib.rs; dependencies aws-sdk-s3, aws-credential-types, aws-smithy-types; dev: aws-smithy-mocks, aws-smithy-http-client (test-util), aws-smithy-runtime-api, tokio.
  • Frontend: src/browse/* (store, navigation, api, loader, panel), src/screens/*, App.tsx reduced to view switching; zustand, vitest and jsdom added.
  • Tests: 29 Rust tests (19 new: 17 in s3/local/app_error, 2 duplicate_profile), 16 vitest tests.

Tradeoffs

  • Mocks: aws-smithy-mocks for listing and error mapping; a capturing HTTP client for config behaviour (the SDK Config has no getters for endpoint or path style, so the test inspects the real request URI, signing header and checksum headers instead).
  • Pagination: one page per call, the UI loads the next page when the cursor nears the end; chosen over loading everything so a huge prefix opens fast. Buckets are not paginated (ponytail).
  • Virtual list: a small fixed-row-height windowing component instead of a library; fine for uniform rows.
  • Errors: new commands return a serializable AppError; the older vault commands keep returning strings to avoid churn.
  • Client cache: one client for the active profile, cleared on lock, save and delete; profile_test uses a fresh client so it always tests current settings.
  • Not exercised: no real MinIO, no running app (tauri dev not run), UI behaviour (keyboard, scrolling, virtualisation) only type-checked and built, not clicked through.
