Resizable columns in each panel (step 3g)

Specs

  • Drag the border between header cells to change Ext, Size and Date; Name takes the rest. Per-panel widths in the store layout slice, persisted in localStorage under its own versioned key, guarded and clamped, UI works without storage.
  • Min/max per column so <DIR> and a full date fit at the minimum; double-click resets a column; each border is a focusable role="separator" with ArrowLeft/ArrowRight (Shift = bigger step) and Home; pointer events with capture, no HTML5 drag.
  • Header and rows share widths; Date still hides in a narrow panel; Name never collapses below a minimum; sort, context menu, drag and drop, marks and keyboard navigation do not regress.

Actions

  • New src/browse/panel_columns.ts: limits (Ext 48..160, Size 80..200, Date 120..220), clampWidth, stepWidth, resetWidth, fitWidths, guarded loadColumns/saveColumns (key s3c.panel-columns.v1).
  • New src/browse/column_resizer.tsx: the separator component (pointer capture, keys, double-click).
  • browse_store.ts: columnWidths, setColumnWidth, resetColumnWidth. file_panel.tsx: measures the panel, publishes --w-ext/--w-size/--w-date, renders a resizer in the Ext, Size and Date header cells. styles.css: the single .row template reads the variables (also in the container and media rules), .col-resizer block appended.
  • Tests: panel_columns.test.ts (pure functions, persistence with garbage and throwing storage) and column_resizer.test.tsx (semantics, drag, keyboard, double-click, no sort on drag, per-panel, remount, Name minimum, narrow panel). README, CHANGELOG and docs/claude/rule.md updated. No Rust change.

Tradeoffs

  • Border on the left edge of a column, drag left widens. Dragging the right edge of Ext would push Size and Date out of the panel because Name is the flexible column; the left-edge rule keeps the right edge of each column fixed. Consequence: the border between Ext and Size resizes Size, not Ext.
  • The store keeps the user's widths; the panel fits them for display. Shrinking a panel never rewrites the stored value, so growing it restores the choice. Cost: dragging beyond what the panel can show changes the stored value without a visible change until the panel grows (inferred to be acceptable, not user-tested).
  • Name minimum is 96 px, but the column minimums win. In a 240 px panel Name is about 70 px (the same as before this change); the minimums for <DIR> and the date are not broken to save Name.
  • Narrow panel (420 px or less) widths: the Size column now follows the user width (minimum 80) instead of the old fixed 72 px, so a narrow panel has 8 px less for Name than before.
  • The 420 px threshold exists twice (CSS container query and HIDE_DATE_PX); a CSS custom property cannot be used in a container query condition, so a comment in both places and a rule line in rule.md keep them in sync.

Evidence: measured vs inferred

  • Measured: 349 Vitest tests pass; npm run build succeeds; in a Chromium mock (fake data, Vite on port 1437) real mouse drags changed only the dragged column (Size 84 to 134, Ext 56 to 48), a header sort stayed Name ascending after drags, the minimum widths were 48/80/120, Shift+ArrowLeft on a focused Date border widened it 124 to 156, a 238 px panel hid Date.
  • Inferred, not exercised: the real Tauri window and WebKit pointer capture, a Retina display, real keyboard use, the character-width assumption behind the minimums (about 7.5 px per mono character at 12 px).
