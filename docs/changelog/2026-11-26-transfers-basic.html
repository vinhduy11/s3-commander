Basic file operations and transfers (roadmap step 3a)

Specs

Copy, Move, New folder, Delete and Rename between the two panels (Local and server, in any direction), without drag and drop (3b) and without the context menu (3c). One planner for upload, download, server copy and local copy: plan first (count, size, conflicts), then run. Move = copy, verify, delete the source; a failed item keeps its source. Conflicts are decided per item (Overwrite, Skip, Keep both) with Overwrite all, Skip all, Keep both all and Cancel before anything runs. Server delete is permanent after a confirm, local delete goes to the Trash. Upload and download are a single streamed PutObject/GetObject, capped at 5 GiB per file (multipart, progress, cancel, resume are step 4). One active profile, no cross-profile copy.

Actions

  • Rust, pure: transfer_plan.rs (locations, key mapping for four directions, destination checks, conflicts, Resolutions map plus default, auto-rename, summary, delete batches).
  • Rust adapters: s3_ops.rs (paginated list without delimiter, head, put, get via temp file, CopyObject, multipart UploadPartCopy with abort, DeleteObjects batches of 1000), local_ops.rs (walk, copy tree, rename with copy fallback, New folder, Trash behind the TrashBin trait), transfer_run.rs (engine: expand, probe, resolve, run, verify, batched source delete, delete, new folder, rename).
  • Tauri commands transfer_preview, transfer_execute, items_delete, folder_create, item_rename in lib.rs; new dependencies trash and tokio (fs, io-util, rt).
  • Frontend src/ops/: api wrappers, pure target selection, dialog store, flows, dialogs; F-key bar enables F2 and F5 to F8; browse_store gained clearMarks; tokens and styles for modal dialogs.
  • Tests (TDD, red first): Rust 92 total, all mocked SDK or tempdirs with a fake Trash; Vitest 50 total (28 new) for targets, destination, dialog flow, per-item and "all" resolution, Cancel runs nothing, refresh, Esc/Enter.
  • Docs: README, CHANGELOG, architect.md, commands.md, rule.md, roadmap conflict line.

Tradeoffs

  • Re-planning at run time instead of keeping a server-side plan: no plan state to expire, at the cost of one more listing; the preview and the run can differ if the source changes in between (the run uses the fresh state).
  • Conflicts are per file, folders merge. "Keep both" renames the file, not the folder; keep-both names are probed so an existing "(1)" is skipped.
  • Resolution keyed by the destination label (path or bucket/key): simple for the UI and unambiguous inside one operation.
  • Verify = destination size equals the planned size (HEAD or file metadata), not a checksum: cheap, catches truncation, not corruption.
  • Server sources of a move are deleted in one batch after the loop; a crash between copy and delete leaves duplicates, never loss.
  • Empty folders and folder markers are items of their own so structure survives; symlinked folders are refused rather than followed.
  • Local delete runs the Trash call inline in the async command (fast, small lists); move it to a blocking task if it ever stalls the UI.
  • Not exercised: real MinIO, a real Tauri window, the real Trash, WebKit. Everything is measured through mocks, tempdirs and jsdom.
