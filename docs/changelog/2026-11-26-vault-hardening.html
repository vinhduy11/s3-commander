Vault hardening: auto-lock, unlock throttle, Argon2 upgrade (step 6a)

Specs

  • Auto-lock after idle (1, 5, 15, 30, 60 minutes or Never, default 15) from a Settings popover next to Lock; settings kept in a small file in the app data dir; Rust stays authoritative for the lock; unsaved viewer edits must survive a lock.
  • Unlock throttle: exponential delay (1 s doubling to 5 minutes), persisted, reset on success, refusal before any Argon2 work, countdown on the master-key screen.
  • Argon2id parameters in the vault header (old vaults unchanged), stronger target for new vaults, verified in-place upgrade on a correct unlock, never touching the old file on failure.
  • Fewer master-key copies in Rust; honest documentation of what cannot be zeroized.
  • Out of scope: changing the master key, OS keychain / remember on this device (6b), Linux docs and CI.

Actions

  • Rust: new settings.rs and unlock_throttle.rs; vault.rs reworked around KdfParams, open_file / seal_file, unlock_with_hook and upgrade; lib.rs commands vault_unlock_wait, settings_get, settings_set, master key wrapped in Zeroizing; argon2 with the zeroize feature; dev profile optimises argon2 and blake2.
  • Frontend: src/security/ (idle_timer, use_auto_lock, settings_store, settings_popover), master_key_screen countdown, keepUnsavedForLock in viewer_store, App.lock wiring, BrowserScreen no longer clears the viewer on unmount, Settings button on the browser and profiles bars, popover styles.
  • Tests: 18 new Rust tests (settings 6, throttle 7, vault 10 incl. v1 fixture built with the old parameters) and 26 new Vitest tests (idle timer 8, viewer lock 4, master-key screen 6, popover 8). Docs: README, CHANGELOG, architect, safety, rule.

Measured

  • cargo test 277 passed, 1 ignored (benchmark); cargo check no warnings; npm test and npm run build pass.
  • Argon2id derivation time on one Apple M1 Pro (dev build, argon2 at opt-level 3, 5 runs): old 19 MiB / 2 passes about 15 ms; 64 MiB / 3 about 95 ms; 128 MiB / 3 about 195 ms; 256 MiB / 3 about 0.5 s; 512 MiB / 3 0.8 to 1.0 s; chosen 256 MiB / 4 passes / 1 lane 0.50 to 0.55 s.
  • Chromium mock screenshots (in-page mock of the Tauri commands, fake data), light and dark: the Settings popover and the master-key screen during a wait. A first screenshot showed "Never" wrapping to a second row; the popover was widened and the check repeated.

Inferred, not exercised

  • A real vault of the owner, the real Tauri window and real idle behaviour, a slow machine (the time scales with memory bandwidth; a weak machine may take several seconds), a release build, Linux.
  • That the webview delivers pointer, key, wheel and focus events to the window listeners in every case (tested in jsdom only).
  • Memory behaviour of 256 MiB on a low-memory device (not measured).

Tradeoffs

  • Version 2 file with a kdf header (serde default = old parameters) instead of leaving the version at 1: an older build then refuses the file instead of failing with a confusing key error; the cost is that downgrading the app after an upgrade is not possible.
  • 256 MiB / 4 passes / 1 lane, not 512 MiB: about 0.5 s here without asking a small machine for half a gigabyte; the extra pass raises the time at constant memory. It is at the lower end of the 0.5 to 1 s aim on a fast machine, so slower machines land closer to 1 s or above.
  • Upgrade verifies by deriving again and decrypting the temp file (three derivations once) instead of only checking the bytes: it exercises the real unlock path at the price of about 1.5 s on the first unlock.
  • The throttle lives in a plain file and a restart keeps it, but deleting the file resets it: it protects the UI path only; a copied vault is protected by the Argon2 cost.
  • Idle timer records timestamps and uses one timeout instead of resetting a timer on every event: pointer moves cost an assignment.
  • Only unsaved viewer sessions survive a lock, and only in webview memory; clean sessions are dropped so file text does not wait behind the lock screen. Other open dialogs are closed on lock. A manual Lock behaves the same as the auto-lock.
  • Process: tests and implementation were written together for settings and throttle; the red output was produced afterwards by neutering the validation and the delay. The Argon2 and frontend tests were written first.
