Presigned URLs for one or many files (roadmap step 3d)

Specs

Create presigned GET URLs for the marked items or the cursor item of a server panel. Folders are expanded (zero-byte folder markers skipped, capped at 1000, count confirmed first). Expiry 1 second to 7 days, default 1 hour; optional download file name for a single file. Entry points: F9 Presign and "Copy presigned URL" in the right-click menu. Result dialog with Copy, Copy all and Save as text file. URLs are never logged or stored. Out of scope: presigned PUT, POST policies, drag and drop, sorting, multipart, View/Edit.

  • Frontend: presignSelection, presign_flow.ts, presign_logic.ts, presign_dialogs.tsx, clipboard.ts, toast.tsx, shared modal.tsx (moved out of ops_dialogs.tsx), F9 button (enabled by selection), context menu entry, styles.
  • Tests, red first (saved outputs): Rust 133 total (21 new), Vitest 257 total. Rust: URL shape, determinism, key encoding, expiry bounds, disposition, batch order and per-item error, expansion, cap, secret never in any URL or error, write_text_file in a tempdir. Vitest: selection rules, menu entry, dialog flow, Copy and Copy all content, URLs cleared on close and unmount, expiry parsing, clipboard fallback.

Tradeoffs

  • Items are sent with full keys; folder expansion is repeated in preview and in generate (two listings) instead of holding server state: simpler, but a folder can change between them.
  • The full folder listing is held in memory before the cap applies (ponytail note in code); fine for thousands of objects, stream it if folders reach millions.
  • Expiry is validated in the form for instant feedback and again in Rust, which is authoritative.
  • The text file is written by our own small command, not by the fs plugin, so the capability stays at dialog:allow-save and no broad file-system scope is granted.
  • The URL list is a dialog state in ops_store, cleared on close and on unmount; it trades convenience (no history of URLs) for never persisting a credential-like value.
  • Measured: cargo test and vitest results, build, Chromium mock screenshots (light and dark). Inferred, not measured: that the Clipboard API or the execCommand fallback works in a WebKit webview inside Tauri; that a presigned URL is accepted by a real MinIO (signature correctness rests on the SDK).
  • Not exercised: real MinIO, a real presigned download, the real clipboard and native save dialog in the Tauri window, WebKit, real keyboard use (F9 may be captured by the OS on macOS).
