View and Edit (F3 / F4): text, CSV, JSON

Specs

  • Owner request: open and edit text, CSV and JSON files. Roadmap step 5: F3 View (read-only), F4 Edit, Enter on a file and View / Edit in the right-click menu, for LOCAL and SERVER files.
  • UTF-8 only; BOM, line endings and trailing newline preserved (untouched file saves byte-identical); 5 MiB cap; non-text or non-UTF-8 shows a message.
  • CodeMirror 6 (approved), offline, lazy chunk; line numbers, undo, search, wrap, Cmd/Ctrl+S, unsaved-changes guard, light and dark from the tokens.
  • JSON: highlighting, validity with line and column, Format, Minify, saving invalid JSON after a warning. CSV: Text | Table, delimiter detection and override, RFC 4180, header toggle, virtualised grid with in-place edits synced with the text.
  • Saves: local atomic with a changed-on-disk check; server PutObject with the original Content-Type and metadata, If-Match or a HEAD comparison; conflicts offer Overwrite, Save as copy or Cancel; panels refresh.

Measured

  • cargo test 222 passed, cargo check clean; npm test 458 passed; npm run build ok.
  • Main bundle 300.8 kB before (the existing dist) to 315.6 kB after (+14.9 kB: flow, store, CSV and JSON modules, entry-point code); CodeMirror, the modal and the grid are a separate 357 kB chunk loaded on first open.
  • Chromium mock screenshots (in-page mock of the Tauri commands, fake data) in light and dark: text viewer, JSON error, JSON formatted, CSV text, CSV table, unsaved guard, changed-on-disk and changed-on-server dialogs. Cmd+S worked in Chromium.
  • Bug caught by a test: doc.toString() in CodeMirror always joins with LF, which would have turned CRLF files into LF on save; fixed with state.sliceDoc().

Inferred, not exercised

  • Real MinIO and whether it honors If-Match on PutObject (mocked only; the HEAD comparison is the fallback).
  • Real files and the real Tauri window, WebKit (the target webview) with CodeMirror and the grid, real keyboard use and IME input, 5 MiB documents (typing latency was not measured).

Tradeoffs

  • Save conflicts are a tagged result (changed), not an error string: the UI branches without parsing text.
  • One GetObject at open (not HEAD then GET): it gives length, ETag, Content-Type and metadata together; the length is checked before the body is read.
  • HEAD check plus If-Match: works on servers that ignore the header, and closes the race where it is supported. A small window remains without support. Local check-then-rename has the same small window.
  • Own JSON tokenizer instead of JSON.parse: positions in WebKit, and Format that does not change number literals or key order, at the cost of about 150 lines.
  • CSV model keeps per-cell source text: edits touch only edited cells, at the cost of holding the raw strings next to the values.
  • Table renders every column of visible rows (rows are windowed): simple, fine to a few hundred columns.
  • Editor text is mirrored into the store on each change (sliceDoc of the document): simple, may cost latency near 5 MiB (unmeasured); debounce if it shows.
  • CodeMirror packages added individually rather than the bundled codemirror package; main bundle grows by 14.9 kB because the flow and pure modules are not lazy.
  • Save as copy continues on the copy (like an editor's Save As); Add/Delete row and column buttons were added to the table for structural edits.
