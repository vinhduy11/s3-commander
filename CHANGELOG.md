# Changelog

## [Unreleased]

### Added
- Multi-select in the file panels. Mouse: plain click selects just that row, Cmd or Ctrl+click toggles it, Shift+click marks the range from the anchor (the row of the last plain or Cmd/Ctrl click, per panel, reset on navigation and source change). Keyboard: Shift+Arrow, PageUp, PageDown, Home and End extend the range, Cmd/Ctrl+A selects all, Esc clears (ignored while a dialog, menu or the viewer is open), `*` inverts, `+` and `-` open "Select by pattern" / "Deselect by pattern" (glob with `*` and `?`, case-insensitive, whole name, with a live match count). Dragging from empty list space draws a rubber band that marks the rows it touches (Shift or Cmd/Ctrl adds, auto-scroll, Esc cancels). The empty-area context menu gets Select all, Invert selection, Select by pattern... and Clear selection. The marked set stays the selection every operation already uses; ".." is never marked.
- Accessibility: the list is a `listbox` with `aria-multiselectable`, rows are `option` with `aria-selected`, and the selection count is announced politely after bulk actions.

### Changed
- The panel footer reads "N selected, <size>" (was "<size> in N marked"). A plain click now clears the marks (it used to only move the cursor); Cmd or Ctrl+click after a plain click keeps that first row selected.

## [1.0.0] - 2026-11-26

First release: macOS DMG (unsigned), dual-pane MinIO file manager.

### Added
- App icon (bucket with up and down transfer arrows, indigo): vector source `src-tauri/icon-source/app-icon.svg` and the generated `.icns`, `.ico` and PNG set in `src-tauri/icons/`; offline copy of the icon options page in `docs/artifact/`.
- "Remember on this device" (roadmap step 6b, off by default). A checkbox in the Settings popover stores the vault's 32-byte derived key (never the master key text) in the OS keychain (service `dev.local.s3commander`, `keyring` crate: Apple Keychain, Secret Service on Linux without a system libdbus). The key is used only at app launch (`vault_unlock_remembered`; the master-key screen shows "Unlocking..." and falls back to the normal form on any failure); Lock and the idle auto-lock require the master key again, and the unthrottled remembered unlock never counts towards the unlock throttle. A stale, replaced or tampered vault deletes the entry silently; turning the option off, Forget and a failed decrypt delete it, and a master-key unlock refreshes it after the Argon2 upgrade changed the key. When no keychain exists the option reads "Not available on this system" and is disabled. New: `key_store.rs` (`KeyStore` trait), `remember.rs`, `settings.json` flag `remember_on_device` (old files load as off), commands `vault_unlock_remembered`, `remember_status`, `remember_set`, `remember_forget`. Documentation: `docs/claude/deployment.md` (macOS DMG, signing and notarization, Linux prerequisites, bundles, CI commands; unverified parts marked), safety and architect notes.
- Vault hardening (roadmap step 6a). Auto-lock: a Settings popover next to Lock (1, 5, 15, 30, 60 minutes or Never; default 15) stored in `settings.json` in the app data dir (`settings.rs`, commands `settings_get`, `settings_set`); an idle timer in the frontend (`src/security/idle_timer.ts`, reset by pointer, key, wheel and focus events) runs the normal Lock flow, which cancels running transfers. Unsaved viewer edits survive a lock and come back after unlock; a clean viewer is dropped. Unlock throttle: failed unlocks are delayed 1 s, 2 s, 4 s ... capped at 5 minutes, persisted in `unlock_throttle.json` (`unlock_throttle.rs`, injectable clock), reset on success; `vault_unlock` refuses with "Too many failed attempts. Try again in N s." before any Argon2 work and the master-key screen shows the countdown with Unlock disabled (`vault_unlock_wait`). Argon2id parameters are now in the vault file header (`kdf`, file version 2; version 1 files mean the old parameters and open unchanged); new vaults use 256 MiB, 4 passes, 1 lane (about 0.5 s measured on one machine) and an older vault is upgraded in place after a correct unlock (new salt, temp file, read back and compare, atomic rename; any failure keeps the old file and unlock still succeeds). Ignored test `kdf_timing` prints the derivation time.
- View and Edit (roadmap step 5): F3 View (read-only), F4 Edit, Enter or double-click on a file (View) and "View" / "Edit" entries in the right-click menu open the file under the cursor in a large in-window viewer, for LOCAL and SERVER files. UTF-8 only (BOM, line endings and trailing newline are kept, so an untouched file saves byte-identical); binary or non-UTF-8 files and files above 5 MiB show a message instead. Editor is CodeMirror 6 (offline, loaded lazily in its own chunk): line numbers, undo and redo, search (Cmd/Ctrl+F), wrap toggle, Cmd/Ctrl+S, tokens-based light and dark theme, unsaved-changes guard on Esc or close (Save, Discard, Cancel). JSON: highlighting, live validity with line and column, Go to error, Format (2 spaces) and Minify that keep number literals and key order, saving invalid JSON after a warning. CSV/TSV: Text | Table toggle, delimiter auto-detected (`,` `;` tab `|`) with a manual override, RFC 4180 quoting, header-row toggle, virtualised grid with in-place cell editing and Add/Delete row and column buttons; edits change only the touched cells. Saves: local is atomic (temp file in the same folder, rename, permissions kept) with a size and modified-time check, server uses PutObject with the original Content-Type and metadata and `If-Match`, falling back to a HEAD comparison; a changed file or object offers Overwrite, Save as copy or Cancel; panels refresh after a save. New Rust modules `text_doc`, `text_s3`, commands `local_text_open`, `local_text_save`, `s3_text_open`, `s3_text_save`; new dependencies `@codemirror/state`, `view`, `commands`, `language`, `search`, `lang-json` and `@lezer/highlight`.
- Resizable columns (step 3g): drag the border on the left edge of the Ext, Size or Date header cell to change that column's width (Name takes the rest; dragging left widens). Each panel has its own widths, kept in the Zustand layout slice (`columnWidths`, so they survive view switches) and persisted in `localStorage` key `s3c.panel-columns.v1` (guarded, clamped per field, garbage falls back to the defaults, works without storage). Limits Ext 48..160, Size 80..200, Date 120..220 px, so `<DIR>`, a size and a full date always fit. Each border is a focusable `role="separator"` (ArrowLeft widens, ArrowRight narrows by 8 px, Shift 32 px, Home or double-click resets that column), pointer events with pointer capture, never sorts. Header and rows share the widths through `--w-ext`, `--w-size`, `--w-date` on the panel and the single `.row` template. A narrow panel shows fewer pixels than the stored widths (Date shrinks first, then Size, then Ext, so Name keeps about 96 px) and the stored widths come back when the panel grows; a panel of 420 px or less still hides Date and the hidden column takes no space.
- Transfer queue (roadmap step 4b). F5, F6 and drops no longer block behind a busy dialog: after the plan and conflict dialogs the transfer becomes a background job (`transfer_start` returns the job id at once), the dialogs close and a queue panel above the F-key bar shows it. Rust job runner (`transfer_job.rs` pure state machine, `transfer_queue.rs`): at most 3 jobs run at once, the rest wait in start order; the items of a job run one after another (parts are already parallel); a move deletes the source only of items that succeeded. Commands `transfer_start`, `transfer_cancel`, `transfer_retry`, `transfer_dismiss`, `transfer_list`; events `transfer://state` (every state change) and `transfer://progress` (about 10 per second per job: job id, current item, item and job bytes, item index and count). Frontend `src/queue/`: collapsed one-line status ("Idle" or "2 running, 1 queued, 40%"), expandable rows with progress bar, current item, bytes, speed (5 s moving window), ETA, item counts, Cancel (running or queued), Retry (failed or cancelled), Dismiss (finished) and an expandable per-item failure list; Esc collapses. Locking the vault cancels every job and aborts their uploads.
- Retry resumes a failed multipart upload: the upload id is kept in the job's memory and Retry continues it through ListParts. Downloads resume from the `.part` file as before.
- Multipart transfer engine (roadmap step 4a, Rust only; no queue UI or events yet). Upload: PutObject below the profile's `multipart_threshold`, otherwise multipart with up to `max_concurrent_requests` parts in flight, each read from the file at its offset, retried 3 times with exponential backoff on dispatch/timeout/5xx (never on 4xx), completed in part order, `AbortMultipartUpload` on permanent failure or cancel (a failed abort is reported with the upload id). Part size = `multipart_chunksize`, raised to 5 MiB and to fit 10,000 parts (`plan_parts`, tested table incl. the 5 TiB limit). `resume_upload` lists the uploaded parts (paginated) and uploads only the missing or size-mismatched ones. Download: ranged GetObject (If-Match the ETag) streamed to `<name>.part` next to the destination with a `.part.meta` sidecar (ETag + size), resumed from its length only when both still match, size verified, atomic rename; cancel removes the temp files, a failure keeps them and says so. New `ProgressSink` trait (upload id, total, bytes done, per-part notification) and `CancelToken`, checked between parts and ranges. Memory is bounded by parts in flight x part size, capped at 1 GiB. New modules `part_plan`, `transfer_control`, `multipart_upload`, `ranged_download`.
- Resizable panels: drag the divider between the two panels (pointer events with pointer capture, 8 px hit area, token-colored line with hover, drag and focus cues). Each panel keeps at least 240 px and the split stays within 20..80 %. The split is stored as a ratio in the Zustand store (`splitRatio`, so it survives view switches) and persisted in `localStorage` (guarded; clamped on load; works without storage). The ratio is kept when the window resizes. The divider is a focusable `role="separator"` (ArrowLeft/Right 16 px, Shift 64 px, Home or double-click resets to 50/50) and is hidden in the narrow single-column layout. A panel narrower than 420 px hides the Date column (container query) so names stay visible. Drop hit-testing already used live DOM geometry; the divider sits outside both panels so it is never a drop target (covered by tests). Reaching the divider with the keyboard needs a click first because the panels use Tab to switch panels.
- Per-profile transfer settings (optional, vault files without them load unchanged): `multipart_threshold`, `multipart_chunksize`, `max_concurrent_requests`, `addressing_style`, edited in a collapsed "Transfer settings" section of the profile form (defaults as placeholders, inline per-field errors). Sizes are AWS-CLI style (bytes or `KB`/`MB`/`GB`/`TB`, 1024-based, case-insensitive, one optional space, no decimals); chunk size >= 5 MiB, threshold must not be below the chunk size (effective values, defaults 8 MiB / 8 MiB), concurrency 1..=256, style `path`/`virtual`/`auto`. Rust (`transfer_settings.rs`, called from `profile_rules.rs`) is authoritative; `validate_profile.ts` mirrors it and both run the same `validation_cases.json`. `effective_transfer_settings` resolves the values with defaults (8 MiB, 8 MiB, 10, `path`) for the later multipart step; no transfer uses them yet.
- "Import from AWS CLI" in the profile form (only on click): commands `aws_config_list_profiles` and `aws_config_read_profile` read `~/.aws/config` (or `AWS_CONFIG_FILE`), parse `[default]`, `[profile x]` and the nested `s3 =` block, and return only the four settings, `region` and `endpoint_url`. Credentials file and every secret key are never read. The result fills the form as an editable preview that goes through the normal validation.
- Presigned URLs (step 3d): F9 "Presign" and "Copy presigned URL" in the right-click menu (server items only) create GET URLs for the marked items or the cursor item. Options dialog with expiry presets (15 minutes, 1 hour default, 1 day, 7 days) or a custom value and unit (1 second to 7 days), optional download file name for a single file (`response-content-disposition`); a folder is counted and confirmed first (capped at 1000 URLs). Result dialog with name and expiry per URL, Copy, Copy all (one URL per line) and Save as text file. URLs are computed locally with the profile credentials (`presign.rs`, no request sent), live only in the open dialog, and are never logged or stored. New commands `presign_preview`, `presign_urls`, `write_text_file`; new dependency `tauri-plugin-dialog` (+ `@tauri-apps/plugin-dialog`) with the `dialog:allow-save` permission for the save dialog.
- Sorting in the panels: click the Name, Ext, Size or Date header (real buttons with `aria-sort` and an arrow) to sort, click again to reverse; the empty-area context menu has Sort by Name / Ext / Size / Date and Reverse order calling the same store actions. Each panel keeps its own sort (default Name ascending, kept across view and source switches, not across restarts). `..` is first, folders stay above files and sort by name only, Name and Ext are case-insensitive with natural number order, ties fall back to Name ascending (`src/browse/sort.ts`).
- Server panels with more pages show "sorted over loaded items" and a "Load all" button in the footer that loads the remaining pages through `loadMore`, stopping at 20,000 items with a message. Local panels never show it.
- Drag and drop (step 3b). In-app, with pointer events: drag rows between the panels or within one; plain drop copies (Upload / Download / Copy), Shift at drop moves; a folder row targets that folder; a drop inside the same panel only works on a folder row and moves; dropping a folder onto itself or its own child, onto "..", or onto a panel without a source is refused with a message. A ghost shows the name or "N items" with a Copy / Move / Not allowed cue; Esc cancels; the list auto-scrolls near its edges. Drops use the F5/F6 plan, conflict, busy and result dialogs.
- Drop files and folders from the OS file manager onto a server panel (Tauri webview drag-drop event, `dragDropEnabled` set explicitly); they upload with their structure. New command `local_stat_paths`. Items must come from one folder.
- Right-click context menu on panel rows and empty panel space (also Shift+F10 / ContextMenu key): Open, Upload/Download/Copy to other panel, Move to other panel, Rename, Delete, New folder, with shortcut hints. Handlers call the same flows as the F-keys. Vitest no longer scans `.claude/` worktrees.
- Profile validation on add and edit. Rust (`profile_rules.rs`) is authoritative and returns per-field errors; the form mirrors the rules (`src/profile/validate_profile.ts`) for inline errors and a disabled Save while invalid. Rules: name required, max 64, unique case-insensitively; endpoint is an http(s) URL with a host, no user info, query, fragment or path, port 1..65535, normalized (trimmed, no trailing slash); access key without whitespace or control characters; secret required on create (blank on edit keeps the stored one), no control characters; region optional (default `us-east-1`), `[a-z0-9-]` up to 32.
- A non-blocking warning for `http://` endpoints (keys travel unencrypted) and a "Test connection" button after a successful save. Saving never checks connectivity.
- Shared test table `src/profile/validation_cases.json` used by both the Rust and the vitest tests.
- Basic file operations (roadmap step 3a, no drag and drop or context menu yet): F5 Copy, F6 Move, F7 New folder, F8 Delete and F2 Rename on marked items or the cursor item, destination = the other panel. One transfer planner covers upload, download, server copy (also across buckets) and local copy; it plans first (counts, size, conflicts), move = copy, verify size, delete source (a failed item keeps its source), server copy uses CopyObject or multipart UploadPartCopy above 5 GiB, server delete uses DeleteObjects in batches of 1000 (folder marker included), local delete goes to the OS Trash.
- Conflicts are decided per item (Overwrite, Skip, Keep both, with Overwrite all, Skip all, Keep both all and Cancel before anything runs) from a resolution map plus an optional default; the dialog shows existing and incoming size and date.
- Commands `transfer_preview`, `transfer_execute`, `items_delete`, `folder_create`, `item_rename`; per-item failures are returned and listed in a result dialog.
- Browse (roadmap step 2): dual-pane UI with a Local panel and a bucket panel per side (Name/Ext/Size/Date, virtualised list, Tab/arrows/Enter/Backspace/Space), profile switcher and Lock in the top bar, disabled function-key bar.
- Rust `s3` module (aws-sdk-s3 with endpoint, path-style, static credentials, checksums only when required; paginated `list_dir`; readable error mapping), `local` module, `AppError`.
- Tauri commands `s3_list_buckets`, `s3_list_dir`, `local_list_dir`, `profile_test`, `profile_duplicate`; the S3 client is cached per active profile and dropped on lock and profile change.
- Zustand panel store and vitest (`npm test`).
- Implementation roadmap (`docs/implement/`) and an interactive dual-pane UI demo (`docs/artifact/`), including local-to-server drag and drop and a right-click action menu.
- Multi-profile support: master-key protected encrypted vault (Argon2id + XChaCha20-Poly1305) in the app data dir, Tauri commands `vault_status/create/unlock/lock` and `profile_list/save/delete`, minimal React screens.
- Tauri 2 project scaffold (React + TypeScript + Vite).

### Changed
- `settings_set` keeps the stored `remember_on_device` flag (only the remember commands change it); `vault_unlock` refreshes the keychain entry after a master-key unlock when the option is on; `Vault` gained `derived_key` and `unlock_with_key` (the file-opening code is shared with the master-key unlock).
- Master key handling: the `master` string of `vault_create` and `vault_unlock` is wrapped in `Zeroizing` for the call and `argon2` is built with its `zeroize` feature; dev builds compile `argon2` and `blake2` with `opt-level = 3` so unlock timing matches release. Locking no longer clears the viewer session when the browser screen unmounts; `App.lock` keeps only unsaved edits, and closes any other open dialog.
- The multipart upload engine no longer aborts on a non-cancel failure (a failed part, a failed complete or a failed resume): the upload is kept so Retry can resume it. A cancel still aborts it (a failed abort is reported with the upload id); Cancel, Dismiss and Lock of a job abort what it kept, a failed abort is reported in the item message. Known risk: the upload id is only in memory, so an app crash or quit leaves an incomplete multipart upload on the server (a "clean up incomplete uploads" tool is a later idea).
- `transfer_execute` is replaced by `transfer_start`; the blocking "Copying..." / "Moving..." dialog and the result dialog for transfers are gone (failures are listed in the queue). Marks of the source panel are cleared when the job starts; the destination panel (and the source panel of a move) is refreshed, keeping the cursor row, when the job finishes.
- Enter and double-click on a file now open it in the viewer (they did nothing before); function keys and the right-click menu are ignored while the viewer is open; the F3 and F4 buttons are enabled.
- The 5 GiB limit on upload and download is removed: `transfer_run` now calls the multipart / ranged engine with the active profile's transfer settings (`effective_transfer_settings`), so a file of any size up to 5 TiB transfers; larger ones fail per item with a clear message. `PlanSummary.too_large_count` and `too_large_message` are gone (the frontend still declares the field and shows a stale "above 5 GiB" notice that never triggers; step 4b removes it). A download now first sends a HEAD to learn the ETag and size, and the SDK's own retry is off for part and range requests so the engine's policy (3 attempts) is the only one.
- Vite dev server no longer watches `.claude/` and `src-tauri/target/`: file changes inside a git worktree under `.claude/worktrees/` stopped page-reloading a running `tauri dev`.
- `addressing_style` now takes effect in the S3 client: `path` (default) forces path style, `virtual` and `auto` use the SDK default (virtual-hosted). `profile_list` summaries carry the four transfer fields (never the secret).
- The `<DIR>` marker moved from the Size column to the Ext column; the Size cell of a folder is empty.
- `profile_save` now fails with `{ message, fields: [{ field, message }] }` instead of a plain string; `VaultError::Validation` replaces the old "x is required" check.
- Endpoint errors now say why: an `SdkError::DispatchFailure` is classified (DNS failure, connection refused, connection timed out, TLS certificate not trusted or invalid, invalid endpoint URL) and shows a trimmed root-cause string from the error source chain; the old generic hint is kept only for an unclassified failure. No change to TLS trust behavior.
- UI redesign, "Modern" direction (visual and layout only, no behavior change): design tokens with light and dark themes (`prefers-color-scheme`), system font stack (offline, no web fonts), inline SVG icons for folders and file types, restyled master-key screen, profiles list/form, top bar, dual-pane header/columns/footer with clear cursor, marked and active-panel states, loading spinner, disabled F-key bar. `App.css` replaced by `tokens.css` + `styles.css`.

### Fixed
- Nothing fixed in step 6b.
- Removed the dead "N item(s) are above 5 GiB" notice and `too_large_count` (Rust stopped sending it with the 4a engine).
- Conflict dialog no longer shows "Overwrite all", "Skip all" and "Keep both all" on the last (or only) conflict, where they repeat the plain choices.
- Panel stuck on "Loading...": a Local listing no longer depends on the profile, so `setProfile` after `profile_list` (fresh launch) no longer drops the first Local response; a bucket source without a profile no longer sets `loading` before returning; a dropped stale response clears `loading` when no newer request owns the panel.
